# Settlivo — agent guide

Settlivo is a hackathon demo of a stablecoin payroll platform: companies issue
invoices, workers approve, settlement runs on a schedule in USDC at a live FX
rate, workers cash out to local currency. Everything is simulated by default.
Read first: [README.md](README.md) (pitch, stack, env), the design spec
[docs/superpowers/specs/2026-10-24-settlivo-demo-mvp-design.md](docs/superpowers/specs/2026-10-24-settlivo-demo-mvp-design.md),
and [docs/demo-script.md](docs/demo-script.md) (what judges will click).

## Source of truth

1. The design spec describes intended behaviour. Code implements it.
2. If a change alters behaviour, routes, data shapes, env vars, or statuses,
   edit the matching spec section in the same commit. README and demo-script
   must agree with the spec; fix them in the same commit too.
3. `docs/superpowers/plans/*` are execution plans. Delete a plan once it has
   been executed (git history keeps it). Never treat a plan as current docs.
4. `.superpowers/` is git-ignored scratch (execution ledger). Do not cite it.
5. `docs/roadmap.md` is future direction, not current behaviour. Do not
   implement from it without first moving that stage into the spec, and
   delete the stage from the roadmap once it ships.
6. `src/app/.well-known/workflow/` is generated by the Workflow build. Do not
   edit or document it.

## Layout

| Path | Role |
| --- | --- |
| `src/lib/domain` | Types, `newId()`, invoice status machine (`transition`), subscription plans (`plan.ts`: tiers, monthly send limit, plan-adjusted fee) |
| `src/lib/db` | The only module that touches storage: `getRedis()` returns Upstash or the local JSON file store (`kv.ts`, `.data/kv.json`); `repo.ts` is the API |
| `src/lib/fx` | Live FX fetch with hardcoded fallback, 6-dp USDC conversion |
| `src/lib/chain` | `ChainAdapter` interface; `simulated` (default) and `testnet` (viem/Base Sepolia); calldata memo codec |
| `src/lib/settlement`, `src/lib/scheduler`, `src/workflows` | Settlement step, Workflow + tick schedulers, approval, retry |
| `src/lib/seed` | Personas with fixed IDs (`org_acme`, `wrk_alice`, …) and deterministic history |
| `src/lib/actions` | Server Actions (`"use server"` files may only export async functions); `workers.ts` and `wallets.ts` hold the worker lifecycle (register / remove / offboard, link requests) and wallet actions |
| `src/lib/queries` | Page data loaders |
| `src/components/ui` | shadcn (base-nova) primitives; `shell`, `invoices`, `worker`, `dashboard`, `payroll`, `approvals` are app components |
| `src/app` | Routes: `(company)/company/*`, `(worker)/worker/*`, `login`, `notifications`, `explorer/tx/[hash]`, `api/*` |

The Workflow builder only discovers `"use workflow"` files reachable from a
Next.js entrypoint. `src/workflows/invoice.ts` is reached through
`src/lib/scheduler` → `src/app/api/invoices/[id]/approve/route.ts`. Keep that
import chain or the workflow silently disappears from the build.

## Conventions

- IDs: `prefix_` + 8-char nanoid (`org`, `wrk`, `inv`, `tx`, `run`, `wd`, `ntf`, `wal`, `lrq`).
- Money: USDC amounts are 6-dp strings, never floats in storage. Local-currency
  amounts are numbers.
- Render amounts only through `components/ui/money.tsx` (`Money`, `Usdc`) or
  `formatMoney`/`formatUsdc` in `src/lib/format.ts`: grouped digits, USDC always
  2 dp on screen (storage stays 6 dp; the tooltip carries the full value),
  `justify` inside table cells so the currency marker sits flush-left and digits
  flush-right.
- No Redis or env access at module top level. Read `CHAIN_MODE` and
  `SCHEDULER` at call time via `chainMode()` / `schedulerMode()`.
- Every write goes through `src/lib/db/repo.ts`; pages never import redis.
- Forms use native `<select>`; shadcn Select is not installed on purpose.
- Schedule pickers use `components/ui/local-datetime.tsx`, which submits an
  ISO string from the browser; never parse `datetime-local` text on the server.
- Pages poll: `components/shell/poller.tsx` hits `/api/tick` then refreshes
  every 3 s. Do not add client state that assumes a single render.
- UI copy is English; theme is dark; keep worker routes usable at 375 px.
- Add a shadcn component (`npx shadcn add <name>`) only in the commit that uses it.

## Dead code and doc hygiene (check before every commit)

- No dependency in `package.json` without an import (`grep -r "from \"<pkg>"` src scripts *.config.ts`).
- No file in `src/components/ui/` without an importer.
- No `export` without an importer outside its own file (tests count). Drop
  the `export` or delete the symbol.
- `.env.example` and `process.env.*` usage match both ways.
- Every route in spec §6 exists under `src/app`, and every route under
  `src/app` is listed in spec §6.
- Removing a feature removes its spec, README, and demo-script mentions in
  the same commit.

## Verify before commit

```bash
npm test && npm run typecheck && npm run build
```

For UI changes also run `npm run dev` and check `/login` returns 200 and an
unauthenticated `/company` redirects (307) to `/login`. For anything touching
a demo-critical path run `npm run e2e` (Playwright, uses `KV_MODE=file`).

## Git

- Small commits, pushed to `main` immediately. `main` auto-deploys to
  https://settlivo.vercel.app and teammates follow the repo during the event.
- Never commit `.env*.local`, `.vercel/`, `tsconfig.tsbuildinfo`.
- Reset demo data with the "Reset demo data" button on `/login` (reset code =
  `SEED_SECRET`), `POST /api/seed` (header `x-seed-secret`), or `npm run seed`
  locally.

## Do not break (demo-critical)

Invoice lifecycle (spec §5.1–5.4), payroll run (§5.5), on-chain memo
verification (§5.6), withdraw (§5.7), KYC block + retry (§5.8), org switcher
(§5.10), worker lifecycle and wallets (§5.11–5.12), subscription plan gate
and Billing (§5.2 plans). The demo script exercises all of them in order.

## Known gaps

- `e2e/` runs the demo script locally against the file store; production
  is seeded through `POST /api/seed`.
- `CHAIN_MODE=testnet` is implemented but untested end to end.
